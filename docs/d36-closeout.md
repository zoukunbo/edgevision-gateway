## 3. 为什么学习变乱：需要纠正的是推进方式

1. **学习日边界没有守住。** D36之后继续安排了D37的termios封装、可停止接收、资源管理，再进入D38的请求编码/响应校验，却一直没有明确宣布切换范围。
2. **把已有测试与样板代码拆成过多小步。** 单独添加声明、包装函数、重复参数校验和测试粘贴，不应该持续占用新的学习步骤；应由助手完成样板，把注意力留给系统行为。
3. **软件进展、硬件证据、Notion状态混在一起。** “没有真实从站”不是“还要继续重构串口”能解决的；PC字节测试、PTY测试、设备事务也不是同一种证据。
4. **文档落后于代码。** 旧结论还描述单次poll/read和19项测试，实际已经有定长/取消/共享截止时间与23项测试。旧快照不能继续当成当前欠账。
5. **原时间表本身超载。** D36标称6h，但五段任务合计7h15m；当前执行页明确要求动态裁剪，而不是机械执行原表全部项目。

上述范围控制责任在教学安排，不应归结为学习者进度慢。不得通过继续添加功能来“修复混乱”。
