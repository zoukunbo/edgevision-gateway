# D32｜TCP 协议帧与 Modbus RTU 对照

## Gateway 应用层帧

TCP 只提供稳定、有序的字节流，不提供应用消息边界。一次 `recv()` 可能只
返回半帧，也可能返回一帧或多帧。因此每条连接都要独占一个
`frame_parser_t`：把每次 `recv()` 得到的字节交给
`frame_parser_feed()`，再循环调用 `frame_parser_next()`，直到返回
`FRAME_NEED_MORE`。

| 字段 | 大小 | 含义 |
| --- | ---: | --- |
| MAGIC | 2 字节 | 固定值 `A5 5A`，用于寻找帧头和重新同步 |
| LEN | 1 字节 | 业务数据长度，当前最大 240 字节 |
| PAYLOAD | LEN 字节 | 业务数据，例如模拟的 Measurement 测量消息 |
| CRC16 | 2 字节 | 对 `LEN + PAYLOAD` 计算 CRC16-Modbus，低字节在前 |

解析器会在两次调用之间保留未完成帧。遇到超过
`FRAME_MAX_PAYLOAD` 的长度或错误 CRC 时，解析器拒绝当前候选帧，丢弃
一个字节后继续寻找下一处 MAGIC。统计信息包括：正确帧数、CRC 错误数、
非法长度数、噪声字节数和缓冲区溢出数。

## 与 Modbus RTU 的对照

| 对比项 | Gateway TCP 帧 | Modbus RTU 帧 |
| --- | --- | --- |
| 传输边界 | TCP 不提供边界，必须由解析器恢复 | 使用串口静默时间间隔区分帧 |
| 帧起点 | 使用两字节 MAGIC | 静默间隔后的第一个字节是设备地址 |
| 长度 | 使用一字节 LEN 明确表示 | 根据功能码和字节数字段推导 |
| 数据主体 | Gateway 自定义业务数据 | 地址、功能码和数据 |
| 完整性校验 | 对 LEN 和业务数据计算 CRC16-Modbus | 对地址、功能码和数据计算 CRC16-Modbus |
| CRC 字节顺序 | 低字节在前，高字节在后 | 低字节在前，高字节在后 |
| 错误后同步 | 拒绝候选帧后继续搜索 MAGIC | 等待新的静默间隔，再检查地址和功能码 |

D38 可以直接复用 CRC16 算法，但不能原样复用 Gateway 的 TCP 帧解析器，
因为 Modbus RTU 的字段结构不同，而且帧边界依赖串口时序。

## 为什么长度字段可能成为内存攻击入口

LEN 字段由通信对端控制。如果程序没有先检查协议最大值和缓冲区剩余容量，
攻击者就可能让程序等待异常大的数据、申请过多内存、读取未收到的数据，
或者写出目标缓冲区。本实现先把业务数据限制在 240 字节以内，再计算完整
帧长；解析器使用固定的 2048 字节暂存区，并拒绝任何放不下的追加数据。

## 验证内容

- 单元测试覆盖半帧、粘包、噪声、非法长度、坏 CRC 后恢复、缓冲区溢出
  计数，以及标准 CRC 向量 `123456789 -> 0x4B37`。
- 确定性测试生成并还原 1000 帧，伪随机分片长度为 1 到 97 字节。
- `gateway --smoke` 在同一 TCP 连接连续发送并处理 100 条字段不同的模拟
  Measurement，再校验 100 个确认消息；7 字节接收缓冲区会稳定触发增量
  拆包和跨帧边界路径。

## OK1126B-S 板端验证

主机在 2026-08-24 通过 ADB 地址 `192.168.0.232:5555` 完成验证。板卡为
aarch64 架构，运行 Buildroot 和 Linux 6.1.141。板载 RTC 错误地显示
2024-01-25，因此不能使用板载时间作为实际验收日期。

使用 Buildroot GCC 12.4.0 SDK 生成 ARM64 发布版程序。发布模式通常会定义
`NDEBUG` 并关闭 `assert()`；CMake 已针对协议测试取消这个宏，确保交叉
构建和发布构建仍会真正执行所有断言。

板端原始输出如下：

```text
frame protocol module tests passed
SMOKE_PASS
gateway smoke passed: framed Measurement loopback; measurements=100 ingress_frames=100 response_frames=100
```

三行输出依次表示：协议模块测试通过、Gateway 冒烟测试通过、Measurement
请求帧和响应帧各成功解析 100 帧。该连续流结果于 2026-08-25 在同一块
OK1126B-S 上复测通过；至此板端 1000 帧协议测试和 100 条 Measurement
整链验证完成。
